# 网页采集配置管理工具

离线版采集配置管理工具，涵盖站点管理、抽取模板编排、代理池配置、限速策略、重试机制、增量采集与数据落盘规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 数据契约 · 映射校验

在「源字段名称 → 目标字段名称」之上补齐了一套可执行数据契约，调用链为
**模板字段 → 映射规则（数据契约/映射版本）→ 字段映射结果（规范化留痕）→ 校验批次**，
对应页面路由 `/contract`，代码集中在 `frontend/src/data/contract/`：

- `types.ts`：契约、映射版本、规范化记录、字段映射结果、校验批次类型；
- `engine.ts`：纯引擎（类型转换、默认填充、必填/唯一性口径、版本发布校验、结果校验），不依赖浏览器；
- `seed-contract.ts`：ORDER-9 等样本（手机号 `13800001111` 按文本保留、邮编缺省 `000000`，
  另含缺值/转换失败/唯一冲突/超范围演示行），预置 MAP-V1 已发布与 MAP-V2 草稿两版规则；
- `contract-store.ts`：localStorage 持久化，负责版本快照、single-flight 并发提交、事务回退与校验批次版本锁定。

口径与事务约定：

- 缺值或类型转换失败均定位到具体**源字段与目标字段**；必填标识与唯一性校验为准，
  整组映射只有关键字段全部满足契约后才能交给结果校验，阻断批次直接拒收。
- 规则变更只追加映射版本、不覆盖历史；历史批次永久引用原版本，新批次按新口径处理。
- 同一映射版本并发提交只生效一次（进程内 single-flight 锁），后到请求读取已生成结果；
  发布/提交事务失败时回退到上一份可用映射版本，类型冲突以必填字段与已发布规则为准。
- 业务面校验批次锁定同一份映射版本，同一业务面不允许按不同版本重复判定；超范围时报告具体目标字段。

验证脚本（Node 下跑，不依赖浏览器）：

```bash
cd frontend
npm run verify:contract        # 引擎层：ORDER-9 规范化、违例定位、版本发布/回退、并发语义
npm run verify:contract-store  # 存储层：single-flight、版本锁定、事务回退
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-config-studio:entries` 这一项，或调用 `resetModule(模块)`。
